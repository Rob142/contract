# Freelance Hub PWA·모바일 대응 계획서

작성일 2026-11-12 · 버전 0.1 (초안)

현재 데스크톱 웹(화면 12개)은 그대로 둔다. 화면 폭이 640px 미만이면 모바일 전용 레이아웃으로 바뀌고, 홈 화면에 설치할 수 있는 PWA로 만든다. 작업 기간은 약 2.5주로 추정한다. 계약서와 금액 데이터는 기기에 캐시하지 않는다.

> 근거: 현재 화면 스크린샷 12장(`mockup_view/`)과 `프리랜서_플랫폼_MVP_기획_구현_설계서.pdf`.
> 소스 코드는 아직 확인하지 못했다. 빌드 도구와 라우팅 방식은 8장에서 확인한다.

---

## 1. 목표와 범위

**목표**
- 안드로이드(Chrome)와 iOS(Safari)에서 "홈 화면에 추가"로 설치하고, 주소창 없는 앱 화면(standalone)으로 실행한다.
- 폭 320–430px 휴대폰에서 12개 화면 모두 가로 스크롤 없이 쓸 수 있게 한다.
- 설계서의 시연 시나리오 10단계를 휴대폰에서 처음부터 끝까지 수행할 수 있게 한다.
- 설계서 원칙을 그대로 지킨다. 사용자 확인 후 반영, 서버 금액 계산, 사용자별 격리, 기밀 보호.

**이번 범위에서 제외**
| 항목 | 제외 이유 / 후속 시점 |
| --- | --- |
| 오프라인 쓰기(인보이스 발행, 입금 기록, 프로젝트 확정) | 중복 청구 방지와 사용자 확정 원칙. 온라인에서만 허용 |
| 오프라인 데이터 열람(계약서, 금액) | 기밀 문서를 기기에 남기지 않음 |
| 웹 푸시 알림 | 설계서상 "알림 자동화"는 후속 범위. iOS는 16.4 이상에서 설치된 PWA만 지원 |
| 카메라로 계약서 촬영 후 PDF 생성 | OCR 품질 검증 범위가 커짐. 후속 검토 |
| 네이티브 앱(스토어 배포) | PWA로 충분한지 먼저 확인 |
| 안드로이드 공유 대상(Share Target)으로 PDF 받기 | 후속 옵션. 다른 앱에서 바로 업로드 가능 |

## 2. 공통 레이아웃 원칙

**브레이크포인트**
| 구간 | 폭 | 레이아웃 |
| --- | --- | --- |
| 모바일 | < 640px | 1열, 하단 탭바, 테이블은 카드 목록 |
| 태블릿 | 640–1023px | 2열 그리드, 상단 탭 유지, 사이드 패널은 아래로 |
| 데스크톱 | ≥ 1024px | 현재 화면 그대로 |

**내비게이션**
- 상단 가로 탭(대시보드·계약서·프로젝트·인보이스)은 모바일에서 **하단 탭바**로 옮긴다. 아이콘과 라벨을 함께 쓴다.
- 상단에는 앱바를 둔다. 페이지 제목, 뒤로가기(상세 화면), 아바타를 놓고, 아바타를 누르면 내 정보와 설정, 로그아웃으로 간다.
- 페이지 우상단의 주요 버튼(새 프로젝트, 계약서 업로드, 인보이스 작성, 입금 기록 등)은 **하단 고정 액션바**로 옮긴다. 목록 화면에서는 플로팅 버튼(FAB)도 쓸 수 있다.
- "나의 워크스페이스" 같은 브레드크럼 라벨은 모바일에서 숨긴다.

**공용 컴포넌트 (새로 만들거나 확장)**
| 컴포넌트 | 역할 | 사용 화면 |
| --- | --- | --- |
| `BottomTabBar` | 모바일 주 내비게이션 | 로그인 이후 전 화면 |
| `AppBar` | 제목·뒤로가기·아바타 | 전 화면 |
| `ResponsiveTable` | 데스크톱은 테이블, 모바일은 카드 목록 | 03, 04, 10 |
| `BottomSheet` | 보조 패널, 입력 폼, 상태 변경 | 05, 06, 09, 11 |
| `StickyActionBar` | 하단 고정 주요 버튼(키보드가 열리면 숨김) | 05, 07, 11, 12 |
| `FilterChips` | 가로 스크롤 상태 필터 | 04, 06, 08, 10 |
| `StatGrid` | KPI 카드 4개를 2×2로 | 03, 10 |

**터치와 입력 기준**
- 터치 대상은 최소 44×44px로 한다. 칸반 카드의 아바타, 체크박스, 뱃지가 해당된다.
- 입력창 글자 크기는 16px 이상으로 한다. iOS가 입력창에 포커스할 때 확대하는 것을 막기 위해서다.
- 금액 입력은 `inputmode="numeric"`, 이메일 입력은 `type="email"`과 `autocomplete`를 쓴다. 날짜는 기본 date picker를 쓴다.
- 금액 표시는 `tabular-nums`로 정렬하고 줄바꿈하지 않는다. 예: `1,000,000원`.
- 높이는 `100dvh`, 여백은 `env(safe-area-inset-*)`로 처리한다. 노치와 홈 인디케이터를 고려한 것이다.
- 체크박스 동의 문구(외부 전송 동의, 원문 확인 등)는 라벨 전체를 눌러도 체크되게 한다.

## 3. 화면별 모바일 전환

| # | 화면 | 현재(데스크톱) | 모바일 변경안 |
| --- | --- | --- | --- |
| 01 | 로그인 | 좌측 히어로 + 우측 폼 | 히어로 숨김. 로고, 한 줄 소개, 폼만 표시. 설치 안내 배너를 노출할 수 있음 |
| 02 | 회원가입 | 좌우 분할, 직업군 select | 01과 같은 구조. 직업군은 기본 select. 약관 동의 라벨 전체를 터치 영역으로 |
| 03 | 통합 대시보드 | KPI 4열, 프로젝트·일정 2단, 청구 테이블 | KPI 2×2. 진행 프로젝트 카드 스택(최대 3개 + 전체 보기). 다가오는 일정 목록. 청구·입금은 카드 목록. "새 프로젝트"는 FAB |
| 04 | 계약서 목록 | 드래그앤드롭 영역, 5열 테이블 | 드롭 영역 대신 "PDF 선택" 버튼 하나(`accept="application/pdf"`, 파일 앱·드라이브에서 선택). 상태 탭은 필터 칩. 검색은 앱바 아이콘. 테이블은 카드(파일명, 직업군·업로드일, 분석 방식, 상태 뱃지). 안내 카드 2개는 접힘 영역으로 |
| 05 | 계약서 상세(분석 전 확인) | PDF 뷰어 + 확인·설정 패널 | 상단 세그먼트 [원문 \| 확인·설정]. 원문 탭은 페이지 단위 지연 렌더링과 핀치 줌. 강조된 조항을 누르면 해당 필드로 이동. "계약 분석 시작"은 하단 고정. 상용 API 선택 시 외부 전송 안내와 동의 체크는 버튼 바로 위에 유지 |
| 06 | AI 분석 결과 | 결과 카드 + 수정 프롬프트 패널 | 요약 숫자(주의·확인 필요·확인됨) 한 줄. 필터 칩. 결과 카드 스택. "원문 보기"는 05 원문 탭의 해당 페이지로 이동. 수정 프롬프트는 하단 시트(선택 개수 표시 → 열기 → 복사). 복사는 Clipboard API(HTTPS 필요). "프로젝트 초안 만들기"는 하단 고정 |
| 07 | 프로젝트 생성 초안 | 3단계 스텝퍼, 2단 폼 | 스텝퍼는 "2/3 프로젝트 초안 확인"으로 축약. 폼 1열. 순서는 기본 정보 → 지급 조건 → 작업 초안 → 연결된 계약서. "추정 초안" 뱃지 유지. "확인하고 프로젝트 생성"은 하단 고정. 중복 탭 방지(전송 중 비활성 + 재전송 키) |
| 08 | 프로젝트 목록 | 카드 3열 + 간트 일정 | 카드 1열. 간트는 "날짜별 일정 목록"으로 바꾸고, 원하면 가로 스크롤 간트를 토글로 제공. 카드/목록 보기 토글은 모바일에서 목록만 |
| 09 | 프로젝트 상세(칸반) | 3열 칸반, 드래그 이동 | 상단 세그먼트 [할 일 2 \| 진행 중 2 \| 완료 2]로 열 하나씩 표시하고 좌우 스와이프(scroll-snap). 상태 변경은 카드 탭 → 액션 시트("진행 중으로 이동"). 터치 드래그는 스크롤과 충돌하므로 기본으로 쓰지 않음. 개요·일정·첨부 탭은 가로 스크롤 탭. "인보이스 작성"은 하단 고정 |
| 10 | 인보이스 목록 | KPI 4열, 5열 테이블 | KPI 2×2. 상태 필터 칩. 카드(번호·프로젝트, 청구/입금 금액, 기한, 상태 뱃지). "초안 금액은 합계에서 제외" 안내 유지. "인보이스 작성"은 FAB |
| 11 | 인보이스 상세 | 문서 미리보기 + 청구·입금 패널 | 순서는 청구·입금 요약(미수 잔액 강조) → 입금 기록 → 청구 근거 → "인보이스 PDF 보기" 버튼. "입금 기록"은 하단 시트 폼(금액·날짜·메모, 잔액 초과 시 즉시 안내). PDF는 새 탭으로 열거나 Web Share API로 공유 |
| 12 | 내 정보와 설정 | 4개 탭, 2단 카드 | 섹션 목록 → 각 섹션 상세 화면. 계좌 정보는 기본 마스킹. "변경사항 저장"은 하단 고정. 여기에 "앱 설치" 항목 추가 |

**새로 필요한 모바일 화면 상태**
- 분석·추출 진행 상태(대기·처리·실패와 단계). 다른 화면으로 나가도 하단 탭바 위에 작은 진행 표시를 유지한다.
- 오프라인 배너("오프라인 상태입니다. 저장·발행은 연결 후 가능합니다").
- 새 버전 안내 토스트.

## 4. PWA 기술 구성

**4-1. Web App Manifest** (`/manifest.webmanifest`)
| 항목 | 값(안) |
| --- | --- |
| `name` / `short_name` | Freelance Hub / FreelanceHub |
| `start_url` | `/dashboard?source=pwa` |
| `scope` | `/` |
| `display` | `standalone` |
| `theme_color` / `background_color` | 브랜드 그린(현재 버튼 색 토큰) / `#F5F7F7` 계열 배경 |
| `icons` | 192·512px PNG, 512px maskable, iOS용 `apple-touch-icon` 180px |
| `shortcuts` (안드로이드) | 계약서 업로드, 새 프로젝트, 인보이스 |
| `lang` | `ko` |

iOS용으로 `<meta name="apple-mobile-web-app-capable">`, 상태바 스타일, 스플래시 이미지(선택)를 추가한다.

**4-2. 서비스 워커**
- 프론트가 Vite 기반이면 `vite-plugin-pwa`(Workbox)를 쓴다. 다른 빌드 도구면 그에 맞는 Workbox 구성을 쓴다. 8장에서 확인한다.
- 등록은 `registerType: 'prompt'`로 한다. 새 버전이 감지되면 토스트를 띄우고, 사용자가 누를 때 적용한다. 폼 작성 중 강제 새로고침은 하지 않는다.

**4-3. 캐싱 전략**
| 요청 | 전략 | 이유 |
| --- | --- | --- |
| 앱 셸(HTML 진입점, JS·CSS 번들, 폰트, 아이콘) | Precache, 빌드 해시로 갱신 | 빠른 실행과 설치 요건 |
| SPA 내비게이션 | `index.html`로 폴백(NetworkFirst) | 오프라인일 때 셸과 오프라인 배너 표시 |
| `/api/v1/**` | **NetworkOnly**(캐시 안 함) | 기밀·금액 정확성. 서버가 계산한 최신값만 표시 |
| `/api/v1/files/**`, 인보이스·입금확인서 PDF | **NetworkOnly** + 서버 `Cache-Control: no-store` | 원본 계약서와 발행 문서를 기기에 남기지 않음 |
| 외부 LLM·추론 서버 | 해당 없음(브라우저가 직접 호출하지 않음) | 설계서: 작업자만 호출 |

**4-4. 설치 흐름**
- 안드로이드·데스크톱 Chrome: `beforeinstallprompt`를 잡아 두고, 대시보드 상단 배너(한 번 닫으면 30일간 숨김)와 설정 화면의 "앱 설치"에서 띄운다.
- iOS Safari: 설치 API가 없으므로 "공유 → 홈 화면에 추가" 안내 시트를 띄운다. standalone 실행 여부(`display-mode: standalone`)를 확인해 이미 설치했으면 숨긴다.

**4-5. 비동기 작업 상태 조회(폴링)**
- 설계서의 폴링(2초 간격, 장시간이면 간격 증가)을 유지한다.
- 앱이 백그라운드로 가면(`visibilitychange`) 폴링을 멈추고, 돌아오면 즉시 한 번 조회한 뒤 다시 시작한다. 배터리와 데이터 절약을 위해서다.

## 5. 기밀·금액 원칙과 PWA

설계서 9장의 원칙을 모바일과 설치형 앱에서도 지키기 위한 규칙이다.

- **기기에 남기지 않는 것:** 계약서 원본, 추출 텍스트, 분석 결과, 금액, 발행 PDF. Cache Storage, IndexedDB, localStorage 어디에도 저장하지 않는다.
- **localStorage 허용 범위:** UI 편의 상태만 저장한다. 설치 배너를 닫은 시각, 마지막으로 연 칸반 열 등이다.
- **오프라인에서 쓰기 차단:** 오프라인이면 발행, 입금 기록, 프로젝트 확정, 분석 시작 버튼을 비활성화한다. 백그라운드 동기화로 자동 재전송하지 않는다. 사용자가 다시 연결된 상태에서 직접 확정해야 한다.
- **재전송 키:** 모바일은 네트워크가 끊기기 쉬워 재시도가 잦다. 발행, 입금, 프로젝트 확정 요청은 설계서대로 재전송 키를 반드시 보낸다. 버튼 연타를 막는 것도 함께 한다.
- **로그아웃·계정 전환:** 로그아웃하면 API 응답이 남을 수 있는 메모리 캐시(React Query 등)와 SW 런타임 캐시를 비운다. A 계정에서 B 계정으로 바꿨을 때 이전 데이터가 보이지 않아야 한다.
- **인증 쿠키:** HttpOnly·Secure·SameSite=Lax 이상으로 설정한다. iOS에서는 홈 화면 앱과 Safari의 저장소가 분리되므로, 설치 후 한 번 더 로그인해야 한다(안내 문구 필요).
- **HTTPS:** 서비스 워커와 클립보드는 HTTPS(또는 localhost)에서만 동작한다. 실기기 테스트용 HTTPS 환경을 준비한다.
- **화면 노출:** 앱 전환기 미리보기에 금액이 보이는 문제는 웹에서 막을 수 없다. 범위 밖으로 기록만 남긴다.

## 6. 일정

설계서 6주 로드맵과 별개로, 현재 웹이 완성된 상태에서 붙이는 일정이다. 일수는 1인 기준 추정값이다.

**기기 매트릭스**
| 기기 | 브라우저 | 폭 |

**체크리스트**
- [ ] 320px 폭에서 12개 화면 모두 가로 스크롤 없음
- [ ] 데스크톱(≥ 1024px) 화면이 현재 스크린샷과 동일(회귀 없음)
- [ ] 안드로이드 Chrome에서 설치 가능(DevTools → Application → Manifest에 설치 가능 오류 없음)
- [ ] iOS에서 홈 화면 추가 후 standalone 실행, 아이콘·스플래시·상태바 정상
- [ ] 설계서 시연 시나리오 1–10단계를 설치된 앱에서 끝까지 수행
- [ ] Cache Storage·IndexedDB에 `/api/v1` 응답과 PDF가 없음
- [ ] 로그아웃 후 B 계정 로그인 시 A 계정 데이터가 한 번도 보이지 않음
- [ ] 오프라인에서 발행·입금·확정·분석 버튼 비활성, 오프라인 배너 표시
- [ ] 네트워크 끊김 중 입금 기록을 재시도해도 입금이 한 번만 등록됨
- [ ] 새 버전 배포 후 토스트 → 적용 시 작성 중인 입력이 사라지지 않음
- [ ] 입력창 포커스 시 iOS 확대 없음, 키보드가 하단 고정 버튼을 가리지 않음
- [ ] 3장 PDF(05 원문)를 중급 안드로이드에서 렌더링할 때 멈춤 없음

**성능 목표(계획값, 실제 측정과 구분해 기록)**
- 모바일 4G 기준 LCP 2.5초 이내, 설치 앱 재실행 시 셸 표시 1초 이내.
- 설계서의 "분석 중 일반 조회 p95 1초 이내"를 모바일에서도 측정한다.

## 8. 확인 필요 사항

코드를 보고 정해야 하는 것들이다.

1. **프론트 빌드 도구와 라우터:** Vite + React Router인지, Next.js인지에 따라 PWA 플러그인과 SW 구성이 달라진다.
2. **스타일 방식:** Tailwind, CSS Modules, styled-components 중 무엇인지. 브레이크포인트를 넣는 방법이 달라진다.
3. **PDF 뷰어:** 05·11의 문서 미리보기가 pdf.js인지 이미지 렌더링인지. 모바일 메모리 대응 방식이 달라진다.
4. **칸반 드래그 라이브러리:** dnd-kit 등을 쓴다면 터치 센서 설정과 액션 시트 중 무엇을 기본으로 할지.
5. **데이터 패칭:** React Query 등의 메모리 캐시를 쓰는지. 로그아웃 시 비우는 지점을 정해야 한다.
6. **배포 도메인과 HTTPS:** 실기기 테스트와 시연을 어느 주소에서 할지.
7. **최종 시연을 모바일로 할지:** 한다면 P1 우선순위를 시연 순서에 맞춘다.
