# Freelance Hub UX 개선 방안

작성일 2026-11-12 · 버전 0.1 (초안)

핵심은 **"지금 무엇을 해야 하는지"가 화면마다 하나로 보이게 하는 것**이다. 기능은 처음부터 끝까지 연결돼 있지만, 각 단계의 다음 행동이 숨어 있거나 같은 개념을 다른 말로 불러 사용자가 흐름을 놓친다. 실제로 "분석 전 확인"이 끝나지 않아 AI 분석 버튼이 나타나지 않았고, 사용자는 AI가 동작하지 않는다고 느꼈다.

> 근거 표시: **[관찰]** 실제 사용·화면 캡처에서 확인한 것, **[추정]** 구현을 보고 예상한 것. 추정 항목은 7장의 사용성 테스트로 확인한다.

| 단계 | 사용자가 하는 일 | 막히는 지점 |
| --- | --- | --- |
| 1. 계약서 업로드 | PDF 올리기 | 직업군을 고르지 않아 회원가입 때 값이 그대로 쓰임 **[관찰]** |
| 2. 텍스트 추출 | 기다리기 | 다른 화면에 가면 끝났는지 알 수 없음 **[추정]** |

| 4. AI 분석 | 직업군·실행 방식 고르고 시작 | 카드가 화면 아래에 있어 안 보임. 확인 전에는 아예 없음 **[관찰]** |

| 9. 입금 기록 | 금액·날짜 입력 | 큰 문제 없음 |

## 3. P0 — 핵심 흐름을 막는 문제

### A. 계약서 상세를 "단계 안내형"으로

**문제** [관찰]
- 오른쪽 열에 카드 4개(분석 전 확인 → 분석 설정 → 비교 필요 페이지 → 삭제)가 세로로 쌓여 있다. "분석 설정"은 첫 화면 아래에 있고, 확인 전에는 아예 나타나지 않는다.
- 사용자는 확인 단계가 AI 분석의 전제라는 걸 몰랐다.

**개선**
- 상단에 진행 표시줄을 둔다: **① 텍스트 확인 → ② AI 분석 → ③ 프로젝트 만들기**. 지금 단계를 강조하고, 다음 단계는 잠긴 이유를 함께 보여준다. 예: "금액·납기·지급 조건을 확인하면 열려요".
- 오른쪽 열에는 **지금 단계의 카드 하나만** 펼친다. 끝난 단계는 한 줄 요약으로 접는다. 예: "확인 완료 · 1,000,000원 · 12.04 · 선금 50%/잔금 50% [수정]".
- 못 찾은 값은 빈칸 대신 **"원문에서 찾지 못했어요 — 직접 입력"**으로 강조하고, 필수 3개 중 몇 개가 남았는지 버튼에 표시한다. 예: "확인 완료 (1개 남음)".
- 입력란에 포커스하면 원문 PDF에서 근거 줄을 자동으로 강조한다. 지금은 "원문 보기"를 눌러야 한다.

**성공 기준:** 처음 쓰는 사용자가 안내 없이 업로드부터 AI 분석 시작까지 도달하는 비율.

### B. 직업군을 계약서마다 고르기

**문제** [관찰]
- 디자인 계약서인데 회원가입 때 고른 "개발"로 저장돼 분석 기본값이 개발 규칙이 됐다.

**개선**
- 업로드 직후(추출 대기 중) 또는 확인 단계에서 "이 계약서의 직업군"을 고르게 한다. 기본값은 사용자 직업군이다.
- 추가 개선: 추출된 제목·업무 범위에 "디자인", "개발" 같은 단어가 있으면 추천값으로 제시한다. 확정은 사용자가 한다.
- 분석 설정의 "검토 직업군"과 같은 값을 쓰게 해 두 곳이 어긋나지 않게 한다.

### C. 분석 결과 판정 정리

**문제** [관찰]
- 한 카드에 기준이 두 개 붙는다. 상태(**미발견·불명확·발견**)와 단계(**주의·확인 필요·확인됨**)가 서로 다른 말이라 의미를 짐작해야 한다.
- 실제 Gemini 분석에서 12개 중 6개가 "주의"였다. "비밀유지 조항 없음"과 "수정 횟수 없음"이 같은 무게로 보인다.

**개선**
- 화면에는 **사용자 행동 기준 하나**만 보인다.
  - **꼭 협의할 것:** 중요도 높음이면서 없거나 모호한 항목. 위에서 최대 3~5개로 묶는다.
  - **확인해 볼 것:** 중요도 중간·낮음이거나 근거 검증에 실패한 항목
  - **문제없음:** 발견됐고 위험이 낮은 항목. 기본은 접어 둔다.
- "미발견·불명확"은 카드 안의 작은 설명으로 내린다. 예: "계약서에서 찾지 못했어요".
- 판정 기준은 규칙의 중요도와 모델의 위험도를 함께 써서 서버에서 정한다. 이 기준을 바꾸면 규칙 버전을 올린다.
- 각 카드에 **"그래서 무엇을 할까"를 한 줄**로 둔다. 예: "수정 횟수와 초과 비용을 거래처와 정하세요 → 수정 프롬프트에 포함".

**성공 기준:** 결과 화면에서 사용자가 "꼭 협의할 것"을 정확히 고르는지(테스트 과제), "주의"의 수.

### D. 대시보드에 "지금 할 일" 목록

**문제** [추정]
- 확인할 계약서, 발행 안 한 초안, 연체 인보이스, 마감 임박 작업이 각 화면에 흩어져 있다. 대시보드는 숫자만 보여준다.

**개선** — "지금 할 일" 카드를 대시보드 맨 위에 둔다. 항목마다 바로 그 화면으로 이동한다.

| 할 일 | 조건 | 이동할 곳 |
| --- | --- | --- |
| 계약서 확인하기 | 상태가 "확인 필요" | 계약서 상세(확인 단계) |
| AI 분석 결과 보기 | 분석 완료 후 아직 프로젝트 없음 | 분석 결과 |
| 초안 발행하기 | 인보이스 초안 | 인보이스 상세 |
| 잔금 청구하기 | 모든 작업 완료 + 미청구 지급 단계 | 인보이스 작성(단계 선택된 상태) |
| 입금 확인하기 | 지급 기한이 지난 미수금 | 인보이스 상세(입금 기록) |
| 마감 임박 작업 | 3일 이내 마감 | 프로젝트 칸반 |

## 4. P1 — 손이 많이 가는 부분

### A. 인보이스 기본값과 발행 전 점검 [관찰]
- **제목:** 고른 항목으로 자동 제안한다. 예: 잔금만 고르면 "브랜드 디자인 잔금".
- **지급 기한:** 지급 조건의 기한("검수 완료일로부터 7일 이내")이나 발행일 + 7일을 기본값으로 둔다.
- **발행 전 점검표:** 초안 화면에 표시하고, 모두 통과해야 발행 버튼이 켜진다. 지금은 발행을 눌러야 오류가 보인다.
  - 지급 요건 확인
  - 지급 기한
  - 발행자 정보(상호·계좌)
- **발행자 정보:** 비어 있으면 점검표에서 바로 "내 정보와 설정"으로 보낸다. 지금은 인보이스에 이메일만 찍힌다.
- **"저장하고 발행"을 한 번에** 할 수 있게 하고, 확인 대화상자는 그대로 둔다.

### B. 프로젝트에 "청구 현황" [추정]
- 프로젝트 상세 요약 줄에 지급 단계별 상태를 보여준다. 예: "선금 50% — 입금 완료", "잔금 50% — 미청구".
- 미청구 단계 옆에 바로 청구할 수 있는 버튼을 둔다.

### C. 화면 사이 연결 [관찰]
- 프로젝트 → 계약서: 기존 화면(09)에 있던 "연결된 계약서" 버튼이 지금은 없다.
- 프로젝트 → 인보이스: 이 프로젝트의 인보이스 목록이 없다.
- 계약서 목록: 분석 상태와 연결된 프로젝트를 한 열로 표시한다.

### D. 처리 완료 알림 [추정]
- 추출·분석이 끝나면 화면 오른쪽 아래에 알림을 띄운다. 예: "브랜드 디자인 용역 계약서 분석이 끝났어요 [보기]".
- 상단 "계약서" 메뉴에 처리 중 표시를 둔다.
- PWA 설치 후에는 푸시 알림으로 확장할 수 있다(설계서상 후속 범위).

### E. 첫 사용 안내 [추정]
- 가입 직후 빈 대시보드에 3단계 시작 안내를 띄운다. 예: "① 계약서 올리기 ② 조건 확인·분석 ③ 프로젝트 시작".
- 가상 계약서로 체험하는 "예시로 둘러보기"를 둔다. 시연에도 쓸 수 있다.

## 5. P2 — 완성도

- **용어 통일:**
  - "확인 완료"(계약서)와 "확인됨"(분석)을 구분해 쓰거나 하나로 맞춘다.
  - 처리 실패 문구에 다음 행동을 넣는다.
  - "산정 전" 대신 "작업 없음"이 더 쉬울 수 있다(테스트로 확인).
- **피드백:** 저장·발행·입금 같은 짧은 성공 알림을 토스트 하나로 통일한다. 지금은 화면마다 다르다.
- **AI 응답 문구:** 결과 제목·설명의 길이와 말투 기준을 프롬프트에 더 구체적으로 둔다. 같은 문서를 두 번 분석했을 때 표현이 크게 달라지지 않게 한다.
- **외부 전송 안내:** 동의하기 전에 실제로 보낼 텍스트(가린 상태)를 미리 볼 수 있게 한다.
- **접근성:** 색만으로 상태를 구분하지 않도록 아이콘·글자를 같이 쓴다. 포커스 이동과 대화상자 키보드 동작을 점검한다(FE-45).
- **모바일:** `PWA_모바일_대응_계획서.md`의 화면별 전환을 적용한다.

## 7. 확인 방법 (사용성 테스트)

- **대상:** 프리랜서 3~5명(디자이너·개발자 섞어서). 가상 계약서와 시연 계정을 쓴다.
- **과제** (안내 없이 수행, 화면 녹화 + 말하면서 하기):
  1. 계약서를 올리고 AI 분석 결과를 보세요.
  2. 거래처와 꼭 협의해야 할 조건 두 가지를 고르세요.
  3. 이 계약으로 프로젝트를 만들고 선금을 청구하세요.
  4. 30만 원이 들어왔다고 기록하고 입금확인서를 내려받으세요.
- **측정:** 과제 성공률, 과제별 시간, 막힌 지점과 그때 한 말, 끝난 뒤 쉬웠는지 1~5점
- **판단:** 막힌 지점이 2명 이상에게서 나오면 우선 고친다. 추정으로 적은 항목은 이 결과로 유지하거나 뺀다.

## 8. 구현 현황 (2026-11-12)

### 화면 연결 지도

모든 화면에서 이전 단계로 돌아가고 다음 행동으로 넘어갈 수 있게 했어요.

| 출발 화면 | 이동할 수 있는 곳 |
|---|---|
| 대시보드 "지금 할 일" | 조건 확인할 계약서, 추출 실패 계약서, 프로젝트 만들 계약서, 청구할 단계(인보이스 작성), 발행할 초안, 연체 인보이스, 마감 임박 작업의 프로젝트 |
| 대시보드 청구 표 | 인보이스, 거래처 이름으로 해당 프로젝트, 인보이스 전체 보기 |
