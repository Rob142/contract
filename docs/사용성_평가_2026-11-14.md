# Freelance Hub 사용성 평가 (2026-11-14)

핵심 흐름은 끝까지 막힘 없이 돌아가지만, 실제 프리랜서가 쓰기에는 "다음에 뭘 해야 하는지"를 알려 주는 부분이 약하다.
**동작 완성도는 높고, 사용 흐름 완성도는 중간**이다.

## 평가 방법

- 헤드리스 브라우저(Playwright, Chromium)로 테스트 계정을 만들어 화면을 직접 눌러 보며 확인했다.
- 화면 폭: 데스크톱 1280px, 모바일 390px
- 대상: 개발 서버 `http://localhost:5173`
- 코드는 바꾸지 않았다.

## 써 본 흐름

가입 → 프로젝트 생성 → 작업 진행 → 결과물·증빙 올리기 → 공유 링크 → (클라이언트로) 확인·피드백·수정 요청 3회 → 추가 견적·카운트 제외 → 인보이스 발행 → 입금 기록 → 프로젝트 완료 → 정산 → 포트폴리오 공개

전부 진행됐다. 서버 오류(5xx)나 화면이 깨지는 자바스크립트 오류는 한 번도 없었다.

## 잘 된 점

- **폼 검증이 친절하다.** 빈 값, 잘못된 이메일, 시작일보다 빠른 납기 모두 한국어로 바로 알려 준다.
- **돈과 관련된 안전장치가 탄탄하다.** 발행 전 점검 목록이 계좌 정보가 비면 발행을 막고, 입금 기록은 "실제 입금을 확인했습니다"를 체크해야 저장된다.
- **숫자가 서로 맞는다.** 입금 165만 원을 기록하니 인보이스, 대시보드, 정산 화면, 클라이언트 화면이 모두 같은 값으로 바뀌었다.
- **보안 동작이 의도대로다.** `javascript:` 링크와 `.exe` 업로드는 거부됐고, 공유 링크는 새로고침하면 주소가 사라진다.
- **화면이 깔끔하고 일관된다.** 빈 상태마다 다음 행동 버튼이 있다.

## 확인된 버그

| # | 내용 | 위치 |
|---|---|---|
| B1 | 모바일 정산 화면이 가로로 넘친다. 화면보다 195px 넓어져 하단 탭이 왼쪽 일부만 덮고 본문이 옆으로 밀린다. | `/settlement` (390px) |
| B2 | 카운트에서 제외해도 "포함 횟수 초과" 표시가 그대로다. 1회차를 제외해 2/2가 됐는데도 3회차에 초과 배지가 남는다. | 프로젝트 상세 › 수정 요청 카운터 |
| B3 | 오류 문구 일부가 영어다. 잘못된 링크는 `request validation failed`, 금지된 파일은 `this file type is not allowed`. | 프로젝트 상세 › 결과물·증빙 |
| B4 | 모바일 칸반에 큰 빈 공간이 생긴다. 보이는 열이 비어 있어도 옆 열의 카드 높이만큼 공백이 생기고, 완료 카드는 옆으로 밀어야 보인다. | 프로젝트 상세 (390px) |

### 자잘한 문제

- 확인 기록에 "'시안 제작'를 확인했어요"처럼 조사가 틀린다.
- 포트폴리오 목록의 카드에 검은 기본 테두리가 보인다.
- 포트폴리오 날짜만 `2026-11-02` 형식이다 (다른 화면은 `2026.11.02`).
- 하단 탭 아이콘이 두 쌍 겹친다 (계약서와 서류·정산, 프로젝트와 포트폴리오).
- 서류·정산, 포트폴리오 화면에는 "나의 워크스페이스" 머리글이 없다.
- 정산 표에서 수입이 0원인 달은 누를 수 없는데도 링크처럼 보인다.
- 클라이언트 화면의 인보이스가 "입금 예정 2026.11.30 입금 완료"로 나와 문구가 어긋난다.
- 이름을 적기 전에 "확인했어요"를 누르면 "클라이언트님"으로 기록된다. 이름 칸이 안내 없이 선택 항목이다.

## 흐름에서 막히는 지점

| # | 내용 |
|---|---|
| U1 | **클라이언트가 뭘 남겨도 대시보드는 "밀린 일이 없어요"다.** 피드백 1건과 수정 요청 3건이 왔는데 프로젝트를 열기 전에는 알 수 없었다. |
| U2 | **초과 수정이 경고 없이 접수된다.** 안내문은 횟수를 다 쓴 뒤에야 나오고, 3회차는 확인 없이 바로 들어갔다. 클라이언트 화면에는 어느 요청이 초과인지도, 저장한 20만 원 견적도 보이지 않는다. |
| U3 | **작업을 다 끝내도 프로젝트가 "진행 중"이다.** 완료 처리는 "프로젝트 수정" 창의 상태 선택 안에 숨어 있다. 계약 금액의 절반(165만 원)을 청구하지 않은 채 완료해도 아무 안내가 없었다. |
| U4 | **계약서 없이 만든 프로젝트는 청구가 번거롭다.** 계약 금액이 있어도 항목과 금액을 직접 다시 입력해야 하고, 부가세·원천징수도 수동 입력이다. 저장해 둔 추가 견적도 불러올 수 없다. |
| U5 | **발행자 정보를 발행 직전에야 요구한다.** 인보이스를 다 쓴 뒤 설정 화면으로 갔다가 돌아와야 한다. |
| U6 | **인보이스를 클라이언트에게 보낼 방법이 PDF 내려받기뿐이다.** 공유 페이지에는 번호와 금액만 나오고 PDF는 없다. |
| U7 | **증빙이 단계에 잘못 묶인다.** 직전에 고른 단계가 남아 있어 세금계산서가 "시안 제작" 단계 자료로 올라갔다. 올린 뒤 증빙 입력값도 지워지지 않는다. |
| U8 | **저장 방식이 화면마다 다르다.** 작업 상태와 공유 옵션은 고르는 즉시 저장되는데 저장 버튼은 그대로 있다. |
| U9 | **포트폴리오 공개 페이지가 빈약하다.** 결과물이 글자 링크 두 줄이고, 인용문은 "다만 심볼이 조금 더 단순했으면" 같은 지적이 그대로 실린다. 다듬을 수 없다. |
| U10 | **프로젝트 상세가 길다.** 데스크톱 약 2,500px, 모바일 약 3,500px이다. |
| U11 | **공유 링크를 다시 볼 수 없다.** 새로고침하면 주소가 사라지고, 다시 복사하려면 재발급해야 해서 이미 보낸 링크가 죽는다. 재발급은 확인 없이 바로 실행된다. |
| U12 | **템플릿 단계에 마감일이 없다.** 시작일과 납기가 있어도 단계별 날짜는 전부 "마감일 없음"으로 만들어진다. |
| U13 | **클라이언트 화면에서 피드백과 수정 요청의 차이가 안 보인다.** 입력칸이 한 줄짜리이고, 결과물은 미리보기 없이 글자 링크로만 나온다. |

## 확인하지 못한 것

- 계약서 PDF 업로드와 AI 분석, 계약서로 프로젝트 만들기, 수정 계약 화면 (AI 모델 등록이 필요하다)
- 비밀번호 변경, 인보이스 취소·재발행, 입금 취소, 공유 링크 재발급·끄기
- 실제 휴대폰이나 다른 브라우저(사파리 등)

## 테스트가 남긴 것

개발 DB에 테스트 계정 1개(`ux-test-…@example.com`)와 그 프로젝트·인보이스·첨부 파일이 남아 있다.

## 수정 현황

평가 직후 같은 날 수정하고, 헤드리스 브라우저로 다시 확인했다.

### 고침

| 항목 | 고친 내용 |
|---|---|
| B1 | 격자 칸(`.stack`)이 표의 최소 너비까지 늘어나지 않게 했다. 모바일 정산 화면의 가로 넘침이 0px이 됐다. |
| B2 | 요청을 카운트에서 제외하면 서버가 초과 표시를 회차 순으로 다시 매긴다. 제외 뒤 `3 / 2회`가 `2 / 2회`로 바뀌고 초과 배지가 사라진다. 클라이언트 화면에도 같은 값이 보인다. |
| B3 | 서버 오류 코드를 한국어 문구로 바꿔 보여 준다. 링크 형식은 보내기 전에 먼저 확인한다. |
| B4 | 모바일 칸반을 열 단위로 위에서 아래로 쌓았다. 빈 공간이 없어졌고 완료 카드도 옆으로 밀지 않고 바로 보인다. |
| 자잘한 문제 | 조사(을/를, 이/가), 포트폴리오 카드 테두리, 포트폴리오 날짜 형식, 하단 탭 아이콘, 두 화면의 "나의 워크스페이스" 머리글, 0원 월의 링크 모양, 클라이언트 인보이스 "입금 예정" 문구 |
| U2 | 클라이언트 화면에서 초과 요청에 "포함 횟수 초과" 배지를 보여 주고, 횟수를 다 쓴 뒤에는 확인란을 체크해야 보낼 수 있다. 보낸 뒤 접수 안내가 나온다. 입력칸은 여러 줄이다. |
| U3 | 모든 작업을 마친 진행 중 프로젝트에 "프로젝트 완료 처리" 제안을 보여 준다. 청구하지 않은 금액(계약 없는 프로젝트) 또는 청구 전 지급 단계가 있으면 함께 알린다. |
| U7 | 자료를 올린 뒤 단계·증빙 정보를 비운다. 자료 삭제는 한 번 더 확인한다. 이전 시도의 오류 문구는 새 시도 때 지운다. |
| U11 | "다시 발급"은 이미 보낸 링크가 열리지 않는다는 점을 한 번 더 묻는다. |
| U12 | 템플릿 단계에 시작일~납기 사이를 나눈 마감일을 넣는다. 마지막 단계는 납기와 같다. 날짜가 없으면 비워 둔다. |
| U13 일부 | "확인했어요"가 승인이 아니라는 설명을 붙였다. |
