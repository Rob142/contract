## 1. DB (PostgreSQL · SQLAlchemy · Alembic)

**공통 규칙** (설계서 7장): PK는 UUID, 모든 테이블에 `created_at`·`updated_at`. 금액은 `numeric(14,0)`(KRW 원 단위). 상태·통화·기한은 명시 컬럼. JSONB는 AI 원본 응답 같은 부가 정보만.

### 1-1. 기반 (W1)
- [x] `DB-01` Alembic 초기화, 마이그레이션 명명 규칙, 다운그레이드 가능 여부 원칙
- [x] `DB-02` `users`: email(유일), password_hash, name, job_type, 발행자 정보(발행자명, 상호, 연락처, 입금 은행, 계좌), 기본 실행 방식
- [x] `DB-03` `clients`: owner_id, 업체명, 담당자, 연락처. 로그인 계정 없음
- [x] `DB-04` `files`: owner_id, storage_kind, object_key, size, sha256, mime, 원본 파일명. 로컬 절대 경로는 저장하지 않음
- [x] `DB-05` `audit_events`: actor_id, 대상 종류·ID, 행위, 변경 전후 요약, 시각

### 1-2. 프로젝트·작업 (W1–W2)
- [x] `DB-06` `projects`: owner_id, client_id, contract_version_id(nullable), 명칭, 직업군, 시작일, 납기, 계약 금액, 통화, 상태(진행 중·완료·보관)
- [x] `DB-07` `tasks`: project_id, 제목, 분류 라벨, 상태(todo·doing·done), 정렬 순서, 마감일, 완료 시각, 작업 시간·단가(nullable), 출처(원문 기반·추정 초안·수동)

- [x] `DB-09` `attachments`: 프로젝트·작업 첨부(file_id 연결, 변경 시각)

- [x] `DB-11` `contract_pages`, `contract_text_blocks`: 버전, 페이지 번호, 블록 ID, 위치(bbox), 추출 방식(text·ocr), 품질 점수

## 2. 백엔드 API (FastAPI · `/api/v1`)

**공통 순서** (설계서 8장): 인증 → 소유권 → 입력 검증 → 업무 처리 → 저장 → 응답. 오류 코드: 422 입력, 401 미인증, 403·404 접근 불가, 409 충돌·중복. 금액은 십진 문자열로 주고받는다.

### 2-1. 공통 기반 (W1)
- [x] `BE-01` 앱 골격: 라우터 구조, 설정 로딩, DB 세션 의존성, 트랜잭션 헬퍼
- [x] `BE-02` 공통 오류 응답 형식(code, message, details)과 예외 처리기
- [x] `BE-03` 소유권 검사 헬퍼: 인증 세션에서 owner를 결정하고, 요청 본문의 사용자 ID는 무시. 하위 엔터티는 부모를 거쳐 검증
- [x] `BE-04` 재전송 키(Idempotency-Key) 미들웨어: 발행·입금·프로젝트 확정에 적용, 같은 키는 같은 응답
- [x] `BE-05` 낙관적 잠금: 버전 필드 검사, 불일치 시 409
- [x] `BE-06` 페이지네이션 공통(limit·cursor), 정렬·필터 파라미터
- [x] `BE-07` 파일 저장소 인터페이스: `put·get·delete·presign`. 구현체는 LocalStorage(현재), SupabaseStorage(이전 후)
- [x] `BE-08` 감사 기록 서비스: 발행, 취소, 입금, 삭제, 확인값 변경 시 기록

### 2-2. 인증·사용자 (W1)
- [x] `BE-09` `POST /auth/register`: 이메일 중복 409, 비밀번호 해시(argon2·bcrypt), 약관 동의 필수
- [x] `BE-10` `POST /auth/login` · `/logout`: HttpOnly·Secure 쿠키 세션, 만료, "로그인 상태 유지" 옵션
- [x] `BE-11` CSRF 방어(쿠키 인증일 때 토큰 또는 SameSite + Origin 검사)
- [x] `BE-12` 로그인 시도 제한(rate limit)
- [x] `BE-13` `GET·PATCH /users/me`: 프로필, 기본 직업군, 발행자 정보, 기본 실행 방식

### 2-3. 대시보드·프로젝트·작업 (W2)
- [x] `BE-14` `GET /dashboard`: 진행 프로젝트 수, 이번 주 마감 작업, 발행 청구액, 입금액, 미수액, 다가오는 일정, 청구·입금 현황. 초안 인보이스는 합계에서 제외

- [x] `BE-17` 진행률 계산: 완료 작업 수 / 전체 작업 수, 작업 0개면 "산정 전". 청구 비율로 쓰지 않음

- [ ] `BE-20` 첨부 업로드·목록·삭제, `GET /files/{id}`(소유권 확인 후 스트리밍, `Cache-Control: no-store`)
