[Freelance Hub] 프로젝트 기획 정리

■ 한 줄 소개
프리랜서가 계약서 한 장을 올리면 계약 조건 확인 → AI 계약 검토 → 프로젝트·일정 관리 → 청구·입금 관리까지 한곳에서 이어지는 업무 관리 웹서비스

■ 해결하려는 문제
- 계약서, 일정, 청구서, 입금 기록이 메일·엑셀·메신저에 흩어져 있다
- 계약서의 불리한 조항(수정 횟수, 저작권, 지급 시기)을 놓치기 쉽다
- 어느 단계 금액을 청구했고 얼마나 받았는지 헷갈리고, 중복 청구나 누락이 생긴다

■ 대상 사용자
디자인 · 개발 · 영상 · 마케팅 분야 1인 프리랜서

■ 핵심 기능
1) 계약서 업로드·자동 추출
 - PDF를 올리면 계약 금액, 최종 납기, 지급 조건, 수정 횟수를 자동으로 찾아준다
 - 스캔본은 OCR로 읽고, 원문 위치를 하이라이트해서 보여준다
2) 조건 확인 (사람이 최종 확인)
 - 추출값을 원문과 비교해 확정한다. 확인한 값만 프로젝트와 청구에 쓰인다
3) AI 계약 분석 (선택)
 - 직업군별 규칙과 AI로 빠진 조항·위험한 조항을 찾고, 수정 요청 문구를 제안한다
 - 상용 AI(Gemini 등) 또는 로컬 AI 중 선택. 외부로 보낼 때는 동의를 받고, 이메일·전화·계좌는 가려서 보낸다
4) 프로젝트·일정 관리
 - 계약 조건으로 프로젝트를 자동 생성한다 (지급 단계: 선금·중도금·잔금)
 - 칸반 보드(할 일/진행 중/완료)와 일정 보기를 제공하고, 열 접기·펴기도 된다
 - 계약서 없이 먼저 만든 프로젝트에 나중에 계약서를 연결할 수도 있다
5) 청구·입금 관리
 - 지급 단계별로 인보이스를 작성·발행하고 PDF로 내려받는다
 - 입금을 기록하면 미수금이 자동 계산되고, 입금확인서 PDF를 만든다
 - 같은 단계를 두 번 청구하거나 금액을 초과해 청구하는 것은 시스템이 막는다
6) 수정 계약 반영
 - 선금을 받은 뒤 계약이 바뀌어도, 이미 청구한 금액을 새 계약으로 이월해 이어서 관리한다
7) 대시보드 "지금 할 일"
 - 연체 입금, 확인할 계약서, 청구할 단계, 마감 임박 작업을 급한 순서로 보여주고 바로 이동한다

■ 사용 흐름
계약서 올리기 → 조건 확인 → (AI 분석) → 프로젝트 생성 → 작업 진행(칸반) → 단계별 청구 → 입금 기록 → 완료

■ 서비스 원칙
- AI는 돕는 역할이다. 금액·날짜는 반드시 사람이 확인한 값만 쓴다
- 작업을 완료해도 청구서가 자동 발행되지 않는다. 사용자가 확인한 뒤 발행한다
- 발행한 청구서는 고칠 수 없다(취소 후 재발행). 기록 신뢰성을 위해서다
- 은행 연동 없이 입금은 사용자가 직접 기록한다
- 계약서 원본은 본인만 볼 수 있는 비공개 저장소에 보관한다

■ 화면 구성 (12개)
01 로그인 / 02 회원가입 / 03 통합 대시보드 / 04 계약서 목록 / 05 계약서 상세 / 06 AI 분석 결과 / 07 프로젝트 생성 초안 / 08 프로젝트 목록 / 09 프로젝트 상세(칸반) / 10 인보이스 목록 / 11 인보이스 상세 / 12 내 정보·설정

■ 기술 구성
- 화면: React + TypeScript (Vite)
- 서버: Python FastAPI
- DB: PostgreSQL (청구·입금 규칙은 DB에서도 한 번 더 검증)
- 문서 처리: PDF 텍스트 추출 + Tesseract OCR(한국어)
- AI: 상용 LLM API(Gemini 등) / 로컬 LLM 선택
- 실행 환경: Docker (맥·윈도우 모두 같은 방식)

■ 진행 현황
완료

- AI 계약 분석, 프로젝트·칸반·일정, 인보이스 발행·입금·PDF
- 계약서↔프로젝트 연결/교체/해제, 수정 계약 반영
- 화면 간 연결 개선("지금 할 일", 단계 안내, 바로가기)

남은 것

- 모바일(PWA) 대응

- 실제 사용자 테스트, 배포
